## Defects found and corrected during review

1. A build capture with `output_digest: 'z'.repeat(64)` passed the semantic checker, although the published schema requires a lowercase hexadecimal SHA-256. Reported to the source owner; corrected by enforcing the capture schema before semantic evaluation and tightening the build digest check. The independent negative test now fails that capture as intended. Focused schema tests additionally cover each automatic family and nested fields.
2. An episode marked `TRUNCATED` at `max_steps` could contain a final terminal WIN, pass evaluation, and be counted as a loss/censored episode. Reported to the source owner; corrected to reject terminal/censoring contradictions and post-terminal steps. The independent negative test now rejects the contradictory capture.

Neither correction changes frozen curriculum runtime, policies, seeds, or numerical evidence.

## Task-protocol and runner checks

The actual v0.2 data contain 108 distinct tasks, 494 task criteria and 432 explicit claim-guard bindings. Each task's four guard IDs match the runner's hidden check packet. Removing a guard from both its binding and local required-ID list still invalidates metadata. Self-authored PASS claims and absent captures/reviews do not pass any task. Empty identity-bound automatic captures fail every applicable automatic obligation.

The review exercised the real `runAB` smoke path with `createTaskProtocolPacketEvaluator`, rather than comparing hand-built packet shapes alone. Artifact cleaning and digest binding survive the round trip; guard omissions, altered public materials and altered artifacts are rejected. Synthetic complete review records can exercise the transport, but produce no human result rows. Missing reviews remain eligible failures across both permitted attempts; they do not become empty-check success or an infrastructure exclusion.

This establishes protocol preparation and transport compatibility. It does not establish real candidate correctness for all 108 tasks. Natural-language judgment still needs a qualified blinded reviewer. A supervisor capture identifier, digest, or callback is not an authentication or OS-isolation boundary. Genuine observations must be collected through a separately audited supervisor.

## Executor gates and preservation

The signed-audit route checks frozen audit/source/evidence bytes, a supervisor-provided trusted Ed25519 key, current environment and executor identities, model/settings, budget, hard-limit mechanisms, expiration and required boundary observations. A verified in-memory receipt cannot be forged by copying its fields or transferred to another executor. Boolean isolation/budget claims alone block before invoking the executor. A structurally perfect capability response still reports formal readiness and enforcement as false.

Independent negative tests confirm that over-budget returned submissions preserve their exact raw artifact and counters in private submission/attempt files. An unsettled reservation remains visible, preserves the returned artifact, and cannot produce complete trusted usage. Existing focused integration tests additionally cover provider failure after metering, missing/replayed/reset receipts, evaluator failure, command-transport failure, and first/final attempts across repairs.

These are code gates, not an operational certification. Synthetic tests use ephemeral test keys and inert broker doubles; accepting their signed test record proves the verification path, not the truth of a production audit. The deployed supervisor must exclusively own trusted keys, broker channels, source loading and journal storage. Provider cancellation, provider-enforced token/reasoning ceilings, and actual kernel/host isolation remain unverified in this environment.

Recorded environment failures remain separate: bubblewrap network namespace initialization, the native sandbox app-server directory prerequisite, and the single Codex transport initialization attempt failed before useful execution. Their observations were read and hash-checked, never retried. The preserved handshake has **zero final outputs, zero usage records, zero model events and zero observed tool events**. The status records **zero completed model runs and zero formal A/B trials**. This means no measured provider/model usage, not a measured claim that an executed model cost zero. Recorded human participants remain **0**.

This is not an impossibility theorem about unknown true probabilities or other content pools. V1's earlier failures remain preserved.

## Precise remaining limits

- No completed formal AI+Engine versus AI+Engine+Skill experiment, frozen live model snapshot, measured model effect, or human study exists.
- V3 measures an explicitly synthetic observation-only noisy planner. It does not establish human difficulty, human learning, mastery, enjoyment, or generalization to arbitrary games/layouts.
- The procedural seal is auditable local ordering with committed readable seeds; it is not an independent embargo. Adjusted Wilson coverage is approximate and depends on the within-content trial model. Cross-content shared seeds are disclosed.
- The selector is a width-bounded beam, not a globally optimal solver. The v2 contradiction is stronger only for its specific recorded feasible sets.
- Exact episode accounting applies to the preserved uninterrupted run. Checkpointing is not crash-transactional; interrupted/resumed attempts require separate retention and lifetime accounting.
- Browser/native-engine rendering certification and end-to-end protected candidate execution were not added by this independent offline review.
