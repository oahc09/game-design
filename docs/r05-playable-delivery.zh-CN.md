# R05 可玩交付与验收

范围：接入真实构建器，先以“使用 Game Design Skill 生成一个打飞机小游戏”完成交付，再逐步覆盖其余五类。采用 CocosAirJS 1.0.0/r100 与既有权威 Runtime。工程版本保持 0.2.0，不修改冻结配置、Golden、模型用途/路由或原研究门槛，不用 Windows Sandbox。

## 实际使用

```powershell
node tools/game-design.mjs playable "使用 Game Design Skill 生成一个打飞机小游戏" --directory output/games --out output/build-result.json
# 从结果读取 build_artifact.directory，进入该目录：
npm start
```

每个项目自带 index.html、玩法代码、三份内容、CocosAirJS、许可证和仅监听本机的静态服务器；不读开发仓库，不依赖模型服务、CDN 或 node_modules。每次构建生成新目录，保留旧产物。浏览器不直接打开 file://，按 npm start 输出的 HTTP 地址访问。

实际输入/视觉检查使用独立 Playwright 1.62.1，设置 NODE_PATH 与可选 GD_BROWSER_EXECUTABLE，然后加 --verify-browser --evidence output/evidence。检查器只服务生成目录；先验证清单和文件 SHA256，再读取页面实际载入的全部规格，核对每份 spec hash。缺少浏览器时返回 UNVERIFIED 并保留产物，不能宣称完成。

追加内容：playable "为射击生成2个新关卡内容包" --extend-from <已有目录>。数值修改：playable "调优射击首关数值，再接入引擎，交付可玩的 HTML" --source-project <已有目录> --balance <调优选项.json>。后者保留基线、共同训练种子和独立留出样本，最终构建/页面绑定实际推荐规格。

## 六类产品范围

| 玩法 | 内容差异与操作 |
|---|---|
| 打飞机 | 三段航线：增援、侧翼机群、重型敌机；移动、瞄准、开火 |
| 推箱子 | 三份布局：直接归位、转角墙体、并排箱子；方向键与触屏按钮 |
| 落块 | 中间竖井、侧边竖井、空棋盘；移动、旋转、软降、硬降与暂存，非 Guideline 规则 |
| 三消 | 分数入门，以及原样复用的冻结教学/挑战规格；相邻棋子交换 |
| 2048 | 128、512、2048 三个目标；键盘、触屏按钮和滑动 |
| 拼块 | 托盘与棋盘尺寸差异、2/4/8 条消除目标；先选块再点击位置 |

页面为游戏 HUD、开始/暂停、下一关、胜负、重开和关卡选择，独立于原验证台。render_game_to_text 与 advanceTime 是观测/可重复步进接口；浏览器验收的游戏动作通过真实键盘、鼠标或触屏事件输入，不通过直接改状态制造胜负。另检查无 manual 参数的正常时间循环和全屏入口。

## 18 个开发流程

tools/acceptance-playable.mjs 按六类各三次独立工程请求执行：构建三份内容的可玩项目；实际追加两份不同内容并验证可加载；修改一个首关参数后做共同种子比较、留出验证与重新落地。固定 seed=42，内容生成 seed=73，训练种子 17/42，留出种子 101/211。完整请求、首轮/修复后结果、构建摘要、输入回放、截图、tar.gz 及日志在对应工件中。

打飞机三关均有真实输入胜利回放；其余玩法首关有完整胜利，其他关有加载和实际操作检查；每类均有失败、重开、暂停、失焦和移动布局检查。未据此证明所有后续关卡的人类难度或完整通关率。内容追加的推箱子新关只检查声明的加载与前三步，不将资源受限的完整求解误当无解。

R05 工程状态与数值目标分开：报告状态 PASS_ENGINEERING_ONLY 仅表示交付链路通过。数值样本的预设 competent_completion_rate 目标带仍为 0.5–0.9；六次参数修改的初轮样本均为 1.0，OUT_OF_CONTROL_RANGE 保留，不改带宽、不冻结新推荐、不称为校准通过。样本少，不能用该结果推出总体难度或娱乐性。
单次数值交付 API 同样返回 PASS_ENGINEERING_ONLY，output.status 保持 UNVERIFIED，CLI 非零退出；不能只看已有构建文件就把未达标推荐当完整成功。CI 的 PASS 表示工程验收通过，r05-index 中另列 numerical_gate，原难度门槛未被放宽。

## 真实发现与修复记录

- 首次独立页在引擎导入前缺少固定 canvas 入口，启动失败；修复 GameCanvas 入口。
- 首次输入检查的移动/射击没有到达 Runtime；改为与现有适配一致的捕获阶段键盘处理。
- 移动视口出现内联尺寸造成的横向溢出；仅修正新播放器容器的尺寸覆盖。
- 截图复核发现落块只显示预告、未画棋盘；修复从 rules 读取棋盘尺寸，保留原 Runtime。
- 推箱子第一次浏览器流程成功，但回执含 undefined 字段而无法散列；修复字段序列化，不伪造已完成回执。
- 三消初版目标太容易，多种操作策略都提前完成；保留初版记录，第二/三关改为原样复用已有冻结教学/挑战规格，原冻结文件与目标不变。
- 首轮 18 流程为 17 个工程通过、1 个 UNVERIFIED：新推箱子关卡的部分操作检查额外求完整解而资源受限；移除这个超出已声明范围的求解调用，保留首关完整求解与真实输入胜利要求，修复后 18 个工程流程通过。

本机使用未修改的 develop-web-game Playwright 客户端副本检查动作 burst；只通过启动预载指定本机 Chrome。因工作盘不支持 junction，客户端依赖链接放在独占的系统临时目录，未修改技能原件或全局配置。

## 验收工件与边界

npm run acceptance -- --browser 在干净提交上执行原完整测试、规格、规则、Golden、分发安装、原两页浏览器检查及 R05。Windows/Linux 的浏览器作业包含这些新流程；产物存于 acceptance/<commit>/<job>/r05。运行前后源码摘要必须一致，失败/空套件/跳过不得变绿。

这些是 18 次确定性工程工作流，模型调用为 0，不是 18 个独立模型效果样本，更不是正式 108 项/216 trials。助手看截图不是结构化真人研究。正式 trials=0，外部评审 UNVERIFIED，正式 M7 BLOCKED。Spine 资产和 orientation 13 的既有引擎警告保留；本轮玩法未使用 Spine。
