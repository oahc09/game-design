# M2 — Automatic generation and play framework

## Status

**Executable framework verified with explicit limits.** This report does not certify human playability or every algorithm listed in the master plan. Independent acceptance remains the repository owner's responsibility.

## Completed

- `src/framework/generation.mjs`: bounded, deterministic rejection sampling around each registered archetype generator. Unified controls cover measured difficulty bands, mechanic sets, size, object count, symmetry, explicit randomness metric bands, other target metric ranges, and archetype-specific `custom` controls. Unsupported controls are reported; missing metrics cannot pass a control gate. Every attempted candidate has an accept/reject path.
- `solver.mjs`: working BFS, DFS, A*, Dijkstra, beam search, and an explicit solver registration point. Search reports SOLVED, exhaustive UNSOLVED, TIMEOUT, RESOURCE_LIMIT, or INVALID_STATE. Node, depth, time, and retained-payload memory budgets are enforced. Beam pruning cannot establish unsolvability.
- `player.mjs`: separate observation, decision, and execution stages; independently versioned Random, Greedy, Competent, and Strong profiles; bounded observation history, reaction delay, input frequency, and seeded execution mistakes. Privileged future knowledge is rejected. A policy receives a redacted immutable observation and a separate player RNG, never the runtime, game spec, restore function, or hidden game RNG.
- `simulation.mjs`: all six registered archetypes execute through the same episode interface. Archetype-specific planning defaults are included in profile evidence; explicit overrides take precedence.
- `batch.mjs` and `batch-worker.mjs`: real Node worker threads, deterministic job partitions and output ordering, explicit seeds/profiles/repetitions, machine-readable results, partial batches, atomic checkpoints, and signature-checked resume. Worker count does not enter gameplay identity.
- Trace modes `none`, `summary`, `full`, `failure_only`, and `sampled`. Full state is opt-in. Trace capture has a configurable record limit; omitted records are counted. Reproducible canonical replay actions, event evidence, and state hashes are separate from optional rich traces.
- Simulation emits the **core replay protocol**, using `VERSIONS.replay`, full spec/provenance, initial hash, exact tick/action/acceptance/events/state hash, terminal object, and final hash. All six episode replay types are checked by the core `runReplay` test.
- `materializeSpec(spec, content, seed)` rebinds action-space declarations after content dimensions or batch size change.

## Not Verified

- Human difficulty, human reaction calibration, human enjoyment, adaptive learning
- General stochastic solvability guarantees
- All optional solver algorithms on all archetypes
- Statistical stability on a representative content corpus
- An operating-system heap limit for search; the memory budget measures retained serialized frontier/visited payload, not V8 allocator overhead

## Known limitations

- Generic search is finite-action, fixed-seed **offline oracle** search. It is kept separate from ordinary player policies. A solved trajectory is not a stochastic policy guarantee. Continuous-action shooter search is explicitly unsupported unless a domain solver is registered.
- Generic MCTS and expectimax are not implemented. Archetype-specific expectimax/planning lives in its own package; unsupported algorithm requests fail explicitly. A* optimality requires the caller's heuristic to be admissible.
- Runtime or policy callbacks must themselves be bounded. The framework cannot preempt a synchronous callback mid-call; wall-clock search budgets are checked between expansions/transitions.
- Learning is an interface boundary with observational feedback, not an implemented adaptive learner. Non-default `risk_preference` or `target_priority` overrides are explicitly rejected until policies implement their semantics.
- PARTIAL and NOISY profiles are explicitly unsupported and rejected. DELAYED uses a positive reaction-delay queue over VISIBLE_STATE, including realtime runtimes. Delay cannot exceed the bounded historical-observation memory limit. No calibrated perceptual noise or learned behavior is claimed.
- Generator controls use measured rejection sampling. Some requested ranges are unattainable or unmeasured, and some archetypes do not implement a requested custom control. Such requests return rejections rather than fabricated success.
- `runCount` repeats use separate player RNG streams but can share a game seed. Aggregate confidence intervals are therefore omitted for correlated pooled profiles/repeated seeds; distinct-seed within-profile intervals are available.
- Replay evidence retains action/event/hash entries even with `traceMode: 'none'`. Rich trace state storage is separately bounded. Very long episodes therefore still require memory proportional to their replay length.

## API examples

```js
import { generateContent, materializeSpec, simulateBatch, solve } from '../src/framework/index.mjs';

const generated = generateContent(spec, 42, {
  count: 4,
  max_attempts: 40,
  content_size: { width: 7, height: 6 },
  object_count: 2,
  custom: { pulls: 8 },
});
const candidateSpec = materializeSpec(spec, generated.candidates[0]);
const solved = solve(candidateSpec, {
  algorithm: 'bfs', seed: 7,
  budget: { max_nodes: 20000, max_depth: 80, max_time_ms: 2000, max_memory: 33554432 },
});
const batch = await simulateBatch(candidateSpec, {
  seeds: [7, 11, 23], profiles: ['random', 'competent', 'strong'], workers: 3,
  maxSteps: 300, traceMode: 'failure_only', traceLimit: 100,
  checkpointPath: 'reports/my-checkpoint.json',
});
```

Controls are an envelope; archetype-specific flat generator parameters go inside `custom`. A difficulty target must name an actual metric, for example `difficulty_target: { competent_completion_rate: { min: 0.35, max: 0.55 } }`. Its evaluation seed set and horizon belong in `evaluation`.

## Source-change evidence

`reports/framework-evidence-source-change.json` preserves a run invalidated when Block Puzzle sources changed between parent-process and worker imports. The executable runner now fingerprints core/archetype/framework source before and after a run and only reports `pass: true` when the source stayed unchanged and all equality checks passed. Treat any `source_unchanged: false` artifact as invalid infrastructure evidence.
