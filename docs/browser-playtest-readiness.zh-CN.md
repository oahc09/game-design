# 冻结配置浏览器试玩与真人试跑准备

日期：2026-10-12。当前环境，不用Windows Sandbox，不改变模型路由、规则、玩家策略、冻结规格或包版本0.2.0。本轮使用`game-studio:game-playtest`的启动→输入→状态→截图流程；浏览器为Codex In-app Browser，不把历史WebKit证据当作本次重跑。

## 已修复的入口问题

| 问题 | 修复与实测 |
|---|---|
| 预览默认读取exampleSpec而非冻结规格 | 增加冻结教学/挑战/参考示例选择；生成12份精确规格目录；浏览器WebCrypto核对SHA-256，12份UI显示的id/sha逐一与原冻结绑定一致 |
| 拼块只有机器人单步 | 新增带形状预览的手动选择与棋盘放置；合法放置推进一回合，无效位置显示反馈并保持tick/hash，暂停时点击也保持状态 |
| 三消只显示分数，无法理解颜色收集目标 | HUD显示青色收集进度与剩余步数；首次点击有选择边框，非法交换有反馈；手动交换与暂停点击已检查 |
| 实时短按左键丢失 | 保存修复前导出：只有硬降、没有left输入；缓存短按到下一tick，重测相同左移＋硬降得到WIN，保留前后记录及回放 |
| 控制在大画布下面、窄屏难操作 | 开始/暂停/重开和拼块选择移到画布前；画布适应视口；窄屏HUD字号、布局与证据区可读。390×844截图和点击放置PASS，无横向溢出 |
| 重开/切换遗留交互状态 | 清空按住/短按、交换选择、拼块选择、策略辅助及计时；默认等待“开始”；重开保留当前冻结阶段和种子，回到tick0 |
| 非整数种子显示与实际重放可能不一致 | 校验change/blur，保留最近有效种子；0.5失焦恢复42且状态hash不变，导出使用实际运行种子 |
| 记录不能区分辅助与真人 | 导出规格/来源摘要/真实动作/最终hash、辅助标记、无效尝试、active/elapsed/completion时间；暂停时间不计active，结束后停止计时。手动输入也标为UNVERIFIED_PARTICIPANT，不自动冒充真人 |

[配置目录](../web/calibrated-configs.json)由`node tools/build-playtest-catalog.mjs`生成；原冻结文件不写入，规则数据不重新调优。更新任一冻结来源后必须明确重新生成并核验，不手工改目录来冒充已通过配置。参考示例明确标为未校准，不会在冻结配置缺失/摘要失败时静默降级。

## 实际验证范围

- 12份冻结规格的UI id/SHA绑定通过；每次载入回到READY/tick0，没有启动即倒计时。
- 六类桌面截图及窄屏拼块截图已实际查看，玩法区域与HUD分开，人工操作入口可见。
- 推箱子键盘3步通关，2048键盘移动/暂停，三消手动交换/暂停，拼块合法/无效/暂停点击，落块短按修复，射击短按发射/移动/暂停均实际操作。
- 导出的M3手动/辅助、落块前后、射击、拼块动作在Node参考运行时重建，逐条事件/状态hash一致。策略单步导出assisted=true，普通输入assisted=false，但两者均不是经核验真人参与者。

- 复用41项现有framework测试，未新增tests用例/未重跑全量。页面无运行错误；引擎已有Spine部署/Orientation13提示保留，本轮没有改vendor。

## 真人探索性试跑

当前真人参与者0，真人难度/趣味性结论NOT_RUN。以上全部是助手操作的浏览器检查，不能作为真人研究或独立盲评；原正式M7门槛不因本轮改动自动满足。

本地入口：[试玩页面](http://127.0.0.1:8174/web/index.html)。当前服务绑定127.0.0.1，未部署外网；未来可用`npm run serve`启动默认8173端口，地址相应为`http://127.0.0.1:8173/`。

先由3名真实自愿参与者做探索性试跑，不作总体统计或正式M7验收。使用匿名P001/P002/P003，不记录真实姓名。按匿名编号轮换六类顺序，每类先教学再挑战，seed固定42；试玩中不使用策略辅助/策略单步。正式开始前允许阅读操作说明，但不改冻结参数；实时玩法点击开始才计时。

每局：选择原型与冻结阶段→确认目标/seed→开始并自行输入→结束或主动停止→导出体验记录→填写理解程度、操作舒适度、公平感、愿意继续与具体问题。辅助使用、意外暂停、窗口切换、主动停止等单独标记；有辅助的记录不得作为未辅助样本，失败/中止不从分母删除。

[记录模板](human-playtest-records.csv)只有表头，尚无真人数据。`trace_file`对应参与者导出的本地JSON；`understanding_1_5`等评分必须由实际参与者填写，不能由助手补写。试玩发现需要改规则/难度时，另登记修复与新验证，保留当前冻结及失败证据。
