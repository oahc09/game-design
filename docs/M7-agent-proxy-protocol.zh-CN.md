# M7 代理体验评估：16 个 Agent

2026-11-07 用户将当前计划中的真人参与环节改为 Agent 代理评估。本协议单独登记，不修改既有冻结材料、数值门槛、正式研究资格和历史真人协议，也不将代理数据记作真人数据。它替换当前执行计划中的参与者安排，不能满足原协议的真人有效性要求。

用户随后明确不再要求真人参与：本轮代理流程以成对候选与 16 个 Agent 的实际评估记录为完成条件，不以招募真人为阻塞项。关于真人体验的历史结论仍保持未测量；`gd-108` 原始公开任务保留，要求准备盲法真人对照方案，并非必须完成招募。其方案准备质量与本轮代理观察分开报告，不改写成已有真人结果。

## 执行安排

- 16 个独立新上下文 Agent，模型 `gpt-6-luna`，reasoning effort `high`。同模型重复评估不等于 16 名独立人类受试者，不赋予虚构的新手／熟练玩家身份。
- 用户要求每批并行 8 个；当前工具最多 4 个活跃 Agent，包含主 Agent，因此当前最多并行 3 个评估 Agent。登记按 3/3/3/3/3/1 标记计划分组，实际采用最多 3 个槽位滚动调度，完成一个后补入下一个；每个 Agent 内部任务串行。容量增加后才可采用 8/8，不通过嵌套 Agent 绕过容量。
- 每个 Agent 串行执行 `gd-009`、`gd-019`、`gd-029`、`gd-039`、`gd-065`、`gd-071`、`gd-107`、`gd-108`，每项任务的两个版本也串行操作。
- 每项任务必须具备同任务、同条件的无 Skill／有 Skill 成对候选、可玩入口、产物摘要和必要证据。评估 Agent 不参与这些候选的生成与修复。
- 协调器私下保存组别映射；8 个 Agent 按匿名 X/Y 顺序，另 8 个按 Y/X 顺序。每个评估上下文只获得公开任务、匿名产物和中立输入说明，记录任何来源猜测或泄盲。
- 每版本最多 5 分钟；只记录真实工具操作和实际耗时。代理无需模拟真人的休息、理解时间、放弃行为或人口属性。

## 证据与汇总

先检查候选可启动，再操作键盘／指针并检查画面、行为和错误。只读代码或观看历史截图不能冒充实际游玩；无法操作时记录 `NOT_RUN` 及原因。每条记录绑定 Agent ID、任务、匿名版本、产物摘要、顺序、输入、观察及证据引用。

保留原八个体验维度，但评分明确标记为 `agent_proxy`：理解成本、首次使用容易度、玩法变化、重复性、感知难度、公平性、决策自主性、继续游玩意愿。使用 1–7 分时必须给出观察依据；无法判断填写 null 和原因，主观意愿不冒充人类意愿。实际操作完成状态、失败与评分分开记录。

计划为 16 × 8 = 128 条配对任务评估、256 条版本观察，不是新增正式 A/B trials。按任务、维度、顺序分别报告实际样本数和配对差异；同模型重复评分只作描述，不宣称人类总体显著性。原候选失败不得通过增加 Agent 数量或降低门槛消除。
