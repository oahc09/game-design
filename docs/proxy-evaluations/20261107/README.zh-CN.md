# 16 个 Agent 的八任务代理 A/B

本轮由 16 个独立新上下文的 `gpt-6-luna / high` Agent 完成；每个 Agent 串行观察八项任务及两个匿名版本。用户明确不要求真人参与，因此真人招募不是本轮完成条件。原冻结数据、实现、版本和验收门槛未修改。

完成 8 组成对候选、128 条配对评估、256 条版本观察。请求每批并行 8 个，当前工具容量含主 Agent 为 4，实际使用最多 3 个并行槽位滚动调度，完成一个后补入下一个。前 8 个 Agent 按 X/Y 顺序，后 8 个按 Y/X；每项任务的 X/Y 与组别映射随机，评审前隐藏。

## 候选与验证边界

生成阶段每组一个独立 `gpt-6-luna / high` 上下文，八任务串行；组内存在跨任务上下文相关性。无 Skill 组只获同版 CocosAirJS、中性材料及公开任务；有 Skill 组额外获得完整 Skill。生成者与评审者分离。协调器源码检查发现无 Skill 候选多以 Cocos 背景加 DOM 玩法呈现，有 Skill 候选采用 Cocos 图形绘制玩法；这是实际提交的实现差异，原生引擎一致性仍未认证，不能把视觉偏好等同于引擎验收。

公开浏览器输入检查发现两项首版错误：无 Skill 的 gd-071 返回未定义 events；有 Skill 的 gd-019 缺省 initialBoard 无效。两组均按最多两次尝试完成一次最小修复，原始错误、候选和修复后检查全部保留。预检查工具自身的 URL 路由及 Windows ESM loader 错误另行记录，不计候选失败。候选字节在盲评前冻结，汇总时再次核验。

事后描述性交叉核对：gd-009 的原始快照显示，无 Skill 0/16 次在已推进状态后重开恢复初始快照；有 Skill 14/16 次在已推进状态后重开恢复初始快照。这只核对既有重开要求，未新增主指标或回改代理评分；原评语与可见状态存在差异时保留差异。

浏览器实时循环与 advanceTime 操作并存，两个候选的初始模拟 tick 不保证对齐，因此不据此比较胜率、速度、难度或 FPS 一致性。会话使用各候选默认场景，未覆盖完整同 seed／profile／repeat 矩阵，也未认证默认 seed 已配对。原始评语也不是最终缺陷裁定，例如静态模板棋盘与独立动态坐标可以同时合法，需按公开契约复核。

另一个具体规则问题：gd-019 公开 rule_note 要求隐藏未来方块，有 Skill 候选仍显示下一块预览。此项由评审观察并经协调器公开任务／源码核对，保留问题，不在本轮冻结后修复。

短输入序列和截图不覆盖全部状态／事件／输入／终局一致性、三个渲染帧率、难度校准、缺陷检出率等原始义务；未测不转为通过。gd-108 要求准备盲法对照方案，并不要求完成真人招募；方案交付与真实体验观察分别判断。

16 个 Agent 共享模型和候选，结果高度相关；盲法是流程约束，视觉或错误信息仍可能暴露来源。公开模型别名不是精确快照，宿主子 Agent 缺少可核验的 provider 硬预算计量，不作效率或预算合规增益声明。
