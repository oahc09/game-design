## 修复与依据

接入同一 live game 实例的键盘／指针、固定步进、状态、事件和视觉采集，完整记录每步输入及拒绝前后状态。新增代码仅位于实验候选及实验控制器，未修改根 Runtime、Generator、Router、Evaluator、Schema、Engine Adapter 或冻结配置。

- 推箱子对照候选按实际棋盘宽高布局，重开与已完成状态均验证。
- 方块恢复任务允许的 **一个公开预览**，仅隐藏更远队列、bag、RNG 和原始 runtime。上轮把合法单预览也全部移除的解释过严；本轮按原 `visible_preview_count=1` 校正，并实际验证预览与下一次生成一致，未放宽原门槛。
- 三消只修目标进度投影与 HUD，原目标 100、步数 12 保持；终局实际可达且拒绝后续输入。
- 平台跳跃修正对照候选碰撞／落地，以及 Skill 候选的 y-down 视觉投影和 Space／C／R／P 自动重复边沿。物理参数不调优；跳跃、落地、检查点恢复及真实重复按键均有三帧率记录。持续接触的 COLLIDE 按每固定 tick 采样，不擅加 begin-contact-only 门槛。
- 水排序对照候选补终局保护和整数／范围索引检查。终局后原本合法的倒液被拒绝，实际数字键 9 不污染选中状态；取消可见动画不复制液体。删除未实现的暂停提示及清单条目，保留原规则。
- 卡牌对照候选补真实对手回合，移除以 Pass 扣血替代对手的旧捷径；沿用候选原有卡牌、法力和伤害数字。两组策略只读取最后实际渲染的当前行动方 HUD 与自己的可见行动。延迟首个决策明确记录为不输入，其后使用前一个主体决策机会的计划；固定对手为 immediate。完整日志包含双方实际行动，胜负归一到 P0。

卡牌仍是两套各自声明的简化规则：即时 profile 的 P0 胜率分别为 baseline 12/12、treatment 10/12，延迟 profile 均为 0/12，三帧率一致。[两组指标](metrics-baseline.json) / [Skill 组指标](metrics-treatment.json) 使用全部计划首次执行为分母并列出截尾数。规则、初始生命等并不相同，这些数值不能解释为 Skill 的因果增益。

## 验证边界与保留项

30／60／144 指通过真实 live loop 执行的渲染 delta 调度，不是硬件实测持续 FPS。引擎轨迹与单独执行的原生模型比较；同源模型一致不能独立证明规则正确，因此同时检查冻结公开原生 fixtures、行为见证、三档实际截图及独立源码语义。打飞机、消行、三消终局、动画取消和平台恢复均有具体行为证据。原生规则断言、全部 108 项配置的 schema 完整性要求和原任务门槛均未改写。

16 位评审各检查一个匿名候选，修复版由对应评审继续复核；这不是每位 Agent 重新评价全部 8 项的偏好实验。源码 imports 可能泄露组别，报告如实记录泄盲，不宣称完美盲法。模型路由为 `gpt-6-luna / high`，不代表取得 provider 精确快照或硬预算保证。没有真人数据或虚构评分。

封存前还纠正了监督打包中的任务模板错配、遗漏的原有 `limitations.md`／对照方案，以及旧图片与新摘要不匹配的问题。错误包和旧 FAIL 均保留；仅正确绑定新摘要的候选进入本轮结论。作者说明中的 NOT_RUN 是监督执行前的历史层，当前执行状态在独立采集和评审层记录。旧非通过报告见 [历史索引](historical-reviews.json)，完整材料见 [证据归档索引](evidence-index.json)。
